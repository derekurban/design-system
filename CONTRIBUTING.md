# Contributing

This repository is the source of truth for Derek Urban's design system. Every project pulls a published version from here, and every change lands here first, through an issue and a pull request. Nothing is edited in a consuming project and copied back.

## How a change moves

1. **Issue.** Open one with the matching template: bug, component request or change, or token and foundation change. Say where it's needed.
2. **Branch and pull request.** Branch from `main`, make the change, open a PR that links the issue. Design work done elsewhere (Figma, Claude, a prototype) lands here as a PR like any other change.
3. **Review.** CI builds the package and checks that every component is complete and exported. The owner reviews against the checklist in the PR template.
4. **Squash merge.** The PR title becomes the commit message, so it has to follow the types below.
5. **Release.** A bot keeps a release PR open that collects merged changes, bumps the version and writes the changelog. Merging that PR tags the version, attaches the package to a GitHub release and publishes it to npm.

## PR titles

| Type | Use for | Version bump |
| --- | --- | --- |
| `fix:` | Bugs, contrast fixes, copy fixes in components | Patch |
| `feat:` | New component, prop, variant, token, icon or logo | Minor |
| `tokens:` | Value changes to existing tokens (a shade, a duration) | Patch |
| `docs:` | Guidelines, cards, readme, examples | None |
| `refactor:`, `chore:`, `ci:` | Internal work | None |

Add `!` after the type (`feat!:`, `tokens!:`) when the change renames or removes a token, prop or component, or changes a default so consumers will see something different without opting in. Before 1.0.0 a breaking change bumps the minor version; after 1.0.0 it bumps the major.

Examples: `feat: add Popover`, `fix: focus ring clipped in SegmentedControl`, `tokens!: rename --ink-muted to --ink-tertiary`.

## What a change has to include

- **Components:** `Name.jsx`, `Name.d.ts`, `Name.prompt.md` in `components/<group>/`, the group card updated, and exports added to `src/index.js` and `src/index.d.ts`. `npm run check` enforces this.
- **Tokens:** both themes changed together, contrast still at WCAG AA, `guidelines/` cards still correct.
- **Rules:** if a decision changes, update `readme.md` and `SKILL.md` in the same PR.

## Generated files

`_ds_bundle.js`, `_ds_manifest.json` and `_adherence.oxlintrc.json` are generated by the design tool and used by the cards in `guidelines/` and `components/`. Don't hand-edit them. `dist/` is built in CI and never committed.

## Local setup

```sh
npm install
npm run check
npm run build
```

Open any card or example `.html` file through a local server (`npx serve .`) to preview it.

## Repository settings (owner)

- Branch protection on `main`: require a pull request, require the CI and PR title checks, require review from code owners, allow squash merge only.
- Secret `NPM_TOKEN`: an npm automation token with publish rights to the `@derekurban` scope. Without it, releases still go to GitHub but skip npm.
- Actions → General → Workflow permissions: allow GitHub Actions to create pull requests (needed for the release PR).
